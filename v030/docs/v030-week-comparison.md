### 次週遷移の差と修正

- 修正前のPreview実測ではSeason1 Week2のnode `w2_01`、行動0、TP100、資源・能力保持は正しかったが、画面phaseがHOMEだった。現行版は次週ボタン直後に「WEEK 2｜月曜日」のStoryを自動表示するため、この画面差は意図した変更とは見なさず、互換性の欠陥として `src/domain/progression.ts` を修正した（開始Story nodeがある場合は`phase:"story"`）。修正後に同条件で再実走し、Week2 Storyの自動表示まで確認した。
- 現行版WEEK RESULTの「ダンス平均 C以上」「連携平均 C以上」という文言はnumeric target 45と併記されている。v0.30は現行版のtarget45と達成判定を維持したまま、表示を「平均45以上」へ訂正する。比較シナリオでは達成結果に影響しない。

### 修正後再テストと最終判定（安定Preview）

`progression.ts`、Story cursorの再開処理、ミッションラベル修正を含む安定PreviewでWeek1を再実走した。次週状態は `season=1 / week=2 / node=w2_01 / phase=story / actionsUsed=0 / TP=100`。画面には現行版と同じ「WEEK 2｜月曜日」のStoryが自動表示され、認知度18、ファン2、活動資金¥213,000、能力・体力・EXP・SPもWeek1確定値を保持していた。Week Resultではv0.30が実閾値に沿って「ダンス平均 45以上」「連携平均 45以上」と表示し、達成判定・数値は現行版と同じ。

| 比較項目 | 現行版とv0.30 Preview | 判定 |
|---|---|---|
| 初期ステータス | 4人の歌唱/ダンス/MC/連携/体力、Lv/EXP/SP、共有認知度/ファン/資金/OVKすべて一致 | 差なし |
| TP消費 | 35 + 35 + 20 = 90、残り10 | 差なし |
| 行動回数 | 各行動後1/2/3回使用、週末後3/3、次週0/3 | 差なし |
| 能力・体力 | 3行動とsplit固定成長後の4人全能力・体力が一致 | 差なし |
| EXP / level | SARiNA92、MiYU92、KiLUA74、RAiSA30 / 全員Lv1 | 差なし |

| 結果画面情報量 | v0.30はTP、行動数、週の体力差、EXP/SPも表示し、ミッション名を数値目標に修正 | 意図した明確化。ルール差なし |

**仕様として意図した差:** 新schema (`schemaVersion` と `gameVersion`)、一意ID付き保存、結果画面に追加された週資源・EXP/SPの可視化。比較シナリオの状態計算への差はない。

**不具合として修正した差:** (1) 初回Preview実測では、WEEK 2開始Story nodeは設定されていたがHOMEで待機していた。現行版同様、開始Storyがある週は自動表示するよう `nextWeek()` を修正し、domain testと安定Preview実走で `w2_01` の自動表示まで確認した。(2) HOMEから読んでいた未完了のopening Storyを週末へ進む際に捨てる経路を修正し、未読・中断Storyを再開して完了後に週末Storyへつなぐdomain testを追加した。(3) 現行版のC表記/target45の矛盾は既存のUI不整合として扱い、v0.30では閾値45を維持して数値表記へ修正した。3点とも今回の比較プレイで状態計算・達成判定には差を生まない。

**判定保留／比較範囲:** 今回の同条件プレイは乱数0.5による成功ルート1本で、失敗・大成功の全分岐や1〜700の上位ランク昇格は実プレイ比較していない（Rank/SP境界・成長・二重報酬抑止はdomain unit test対象）。よってそれらまで全組合せの同値性を示すものではない。
